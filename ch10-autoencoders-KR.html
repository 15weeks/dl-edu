Autoencoder

autoencoder와 latent 공간

그림을 숫자 몇 개로 줄였다가(encoder) 다시 그림으로 푸는(decoder) network. 정답 label이 필요 없다: 입력이 곧 정답이다. 잡음 지우기, 가린 곳 채우기, 그리고 15장 생성 model로 가는 latent 공간까지.

1autoencoder: 압축하고 다시 풀기

알고 싶은 것

196 pixel 숫자 그림을 숫자 16개로 줄였다가 다시 그릴 수 있나?

이 절에 나오는 약자

encoder
그림 x를 짧은 code z로 줄이는 앞쪽 network.
decoder
code z를 다시 그림 x̂으로 푸는 뒤쪽 network.
bottleneck, latent code
가운데 가장 좁은 층과 그 값 z (병목, 숨은 code).
  • x 입력 그림 (196 pixel)
  • z latent code (16개)
  • x̂ 복원한 그림

말로: 정답 칸에 입력을 그대로 넣는다. 좁은 가운데를 지나야 하니 network는 "숫자 그림에서 중요한 것"만 16개 숫자에 담는 법을 배운다.

예제: pixel 4개짜리 그림으로 loss 한 번

196칸은 손으로 계산하기 길어서 4칸으로 줄였다. 입력 x와 복원 x̂의 칸마다 차이를 제곱해 평균 낸다.

→ 뜻. 칸마다 평균 0.12 정도(√0.015) 틀렸다는 뜻이다. 2절 이후의 결과(시험 MSE 0.0147 등)도 같은 식을 196칸, 시험 그림 10,000장에 대해 평균 낸 값이다.

기억할 한 줄. autoencoder = encoder(줄이기) + decoder(풀기), loss = 복원 오차. label 없이 배운다.

2denoising autoencoder

알고 싶은 것

입력에 잡음을 넣고 정답은 깨끗한 그림으로 두면?

  • x̃ 잡음 넣은 입력
  • x 깨끗한 정답

결과: 시험 10,000장, 원래 그림과의 MSE

→ 뜻. 잡음이 클수록 효과가 크다 (0.6이면 오차가 1/5로). 잡음은 "숫자다운 모양"에 들어맞지 않으니 좁은 code를 통과하지 못한다.

기억할 한 줄. 입력은 망가뜨리고 정답은 깨끗하게: 그러면 autoencoder가 잡음 지우개가 된다.

3bottleneck에 unit 몇 개가 필요한가

알고 싶은 것

가운데를 1개, 2개, …, 64개로 바꾸면 복원이 얼마나 좋아지나?

결과: network 196-128-k-128-196, 6 epoch, 시험 MSE

→ 뜻. 처음 몇 개를 늘릴 때 가장 크게 좋아지고 32 너머로는 거의 그대로다. 너무 좁으면 흐릿한 "평균 숫자"가 되고, 넓을수록 또렷하지만 압축은 덜 된다.

기억할 한 줄. bottleneck이 좁을수록 압축은 세고 그림은 흐려진다. 오차 곡선이 꺾이는 곳이 알맞은 크기.

4가려진 부분 복원 (occlusion)

알고 싶은 것

그림 일부를 검게 가리고 넣어도 원래 모양을 되살릴까?

결과: 6~9째 줄(4줄)을 가린 시험 10,000장

→ 뜻. 2절의 network를 학습할 때 잡음과 함께 무작위로 2~5줄씩 가렸다. 그래서 남은 획을 보고 "이 숫자라면 가운데는 이랬겠다"를 채운다. 가린 부분이 숫자를 정하는 곳이면 다른 숫자로 채우기도 한다.

기억할 한 줄. 학습 때 가려 본 network는 시험 때 가린 곳을 "그럴듯하게" 채운다. 진짜를 아는 것은 아니다.

5latent code와 latent 공간

알고 싶은 것

code를 2개로 줄이면 숫자들이 평면 위 어디에 놓일까?

말로: 그림마다 평면 위의 점 하나. 아래 평면을 누르거나 끌면 decoder가 그 자리의 그림을 그린다. 시험 MSE 0.030 (2개뿐이라 16개일 때보다 흐리다).

기억할 한 줄. latent 공간 = code들이 사는 곳. 비슷한 그림은 가까이 모이고, 그 사이를 움직이면 그림이 연속으로 바뀐다.

6tied weights

알고 싶은 것

decoder의 weight를 따로 두지 않고 encoder weight를 뒤집어(transpose) 쓰면?

결과: 196-32-196, 같은 학습 조건

→ 뜻. parameter가 절반인데 오차는 오히려 조금 작았다 (이 실험에서). 묶어 두면 encoder와 decoder가 서로 맞물리게 강제되어 정규화(5장)처럼 작동한다.
z    = torch.relu(x @ W.T + b1)          # encoder: W (32×196)
xhat = torch.sigmoid(z @ W + b2)         # decoder: 같은 W를 뒤집어 쓴다 / the same W, transposed

기억할 한 줄. tied weights: decoder = Wᵀ. parameter는 반, 성능은 비슷하거나 낫다.

7생성 model로 가는 다리: latent에서 새 그림

알고 싶은 것

latent 공간의 아무 점이나 decoder에 넣으면 새 숫자가 나올까?

  • z_A 숫자 A의 code
  • z_B 숫자 B의 code
  • z(t) 둘 사이 직선 위의 점

예제: 5절처럼 code가 2개일 때, t = 1/4

A의 code가 (−1, 2), B의 code가 (3, 0)이라 하자. t = 1/4이면 A 쪽으로 3/4, B 쪽으로 1/4만큼 섞는다. 칸마다 따로 계산한다.

→ 뜻. t = 0이면 z_A, t = 1이면 z_B, 그 사이는 두 점을 잇는 선분 위의 점이다. 이 점을 decoder에 넣으면 A에서 B로 바뀌어 가는 중간 그림이 나온다.
이 장의 autoencoder15장의 생성 model
latent 공간에 빈 곳과 모양이 제멋대로VAE: latent를 정규분포 모양으로 맞춘다 → 아무 점이나 뽑아도 된다
잡음을 한 번에 지운다 (2절)diffusion: 잡음을 아주 조금씩 여러 번 지운다 → 순수한 잡음에서 새 그림

기억할 한 줄. data가 있는 곳 사이는 매끄럽게 그려지지만, 어디서 뽑아야 할지는 모른다. 그 규칙을 정하는 것이 생성 model의 일.
