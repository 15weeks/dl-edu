Metrics & Init

Measuring performance and weight initialization

First half: measuring what accuracy alone hides (confusion matrix, precision, recall, F1). Second half: how to set the starting weights so the signal survives even in deep networks (Xavier, Kaiming). Then three FFN projects.

1Two kinds of error: the confusion matrix

WHAT WE WANT TO KNOW

A model that says "positive/negative" can be wrong in two ways. What if we count them separately?

TERMS IN THIS SECTION

TP, TN
true positive / negative. A positive called positive; a negative called negative.
FP
false positive. A negative called positive (a false alarm).
FN
false negative. A positive called negative (a miss).

WORKED EXAMPLE: 500 negatives, 500 positives, threshold 0

→ Meaning. Lower the threshold and misses (FN) fall while false alarms (FP) rise. Which is worse depends on the problem (cancer screening: a miss is worse).

One line to remember. Confusion matrix = two kinds of right (TP, TN) and two kinds of wrong (FP false alarm, FN miss). The threshold trades one against the other.

2Accuracy, precision, recall, F1

WHAT WE WANT TO KNOW

How can the four cells be summed up in a single number?

  • precision share of "positive" calls that are right (higher with fewer false alarms)
  • recall share of real positives that are found (higher with fewer misses)
  • F1 the harmonic mean: high only if both are high

WORKED EXAMPLE: thresholds −1, 0, 1 (the data above)

→ Meaning. Precision and recall pull against each other. Decide which one to protect before setting the threshold.

One line to remember. Precision hates false alarms, recall hates misses, F1 wants both.

3Metrics when the groups differ in size

WHAT WE WANT TO KNOW

What if the same model is used where only 1% are positive? (the imbalance of chapter 8, section 7)

WORKED EXAMPLE: same score distributions, threshold 0, only the share of positives in 1000 changes

→ Meaning. Accuracy stays near 85%, but at 1% positives 19 of every 20 alarms are false. Answering "all negative" would score 99% accuracy. For rare classes, look at precision, recall and F1.

One line to remember. When positives are rare, accuracy says almost nothing. Precision is the first to collapse.

4Timing, and test beating train

WHAT WE WANT TO KNOW

How long does training take? If the test score beats the training score, is it a bug?

import time
t0 = time.perf_counter()
train_one_epoch(net, opt)
print(f"one epoch: {time.perf_counter() - t0:.2f} s")   # on a GPU, measure after torch.cuda.synchronize()
Common reasons for test > trainExplanation
dropout, augmentationThe training score is measured in train mode (units switched off, inputs altered); the test score in eval mode (chapter 5, section 6).
epoch averageIf the training score averages over the epoch, the poor early batches are mixed in.
small test setWith little test data, easy examples can cluster by chance (the wobble of chapter 1, section 10).

One line to remember. Time each epoch with perf_counter. Test > train usually comes from the mode or the data size, not a bug.

6Why weight initialization matters

WHAT WE WANT TO KNOW

What if every weight starts at 0, or at the same value? What if they start too big or too small?

WORKED EXAMPLE 1: XOR, 4 hidden neurons, 1000 epochs

→ Meaning. Start them all equal and the hidden neurons receive equal gradients and stay identical forever (symmetry). Four neurons do the work of one. That is why weights start random.

WORKED EXAMPLE 2: 10 tanh layers (width 64); activation SD at layer 10 for each weight SD

→ Meaning. Too small and the signal fades to 0 layer after layer; too large and tanh sticks to −1 and 1, so its slope vanishes. Either way, training stalls.

One line to remember. Initialise at random and at the right size: too small fades away, too large saturates.

7Xavier and Kaiming initialization

WHAT WE WANT TO KNOW

Can "the right size" be set by a formula?

TERMS IN THIS SECTION

Xavier (Glorot)
X. Glorot and Y. Bengio (2010). An initialization suited to tanh and sigmoid.
Kaiming (He)
K. He et al. (2015). An initialization suited to ReLU. ReLU zeroes half its inputs, halving the variance, so it doubles.
n_in, n_out
The number of inputs and outputs of a layer (fan-in, fan-out).

In words: more inputs means more terms in the sum and a bigger total, so start the weights that much smaller. The aim is for the variance to stay the same from layer to layer.

RESULTS: activation SD after 20 layers (width 64, computed in the browser)

→ Meaning. Match the initialization to the activation. Xavier with ReLU halves the variance at every layer, so after 20 layers it is gone. PyTorch's default for nn.Linear is a Kaiming variant (uniform).
torch.nn.init.xavier_normal_(layer.weight)                         # tanh, sigmoid
torch.nn.init.kaiming_normal_(layer.weight, nonlinearity="relu")   # ReLU

One line to remember. Xavier (2/(n_in + n_out)) for tanh and sigmoid, Kaiming (2/n_in) for ReLU.

8Freezing weights, and how weights change in training

WHAT WE WANT TO KNOW

How much do each layer's weights change? Can some layers be held fixed? (the basis of transfer learning in chapter 12)

for p in net[0].parameters():
    p.requires_grad = False        # freeze layer 1: no gradients for it
opt = torch.optim.Adam(
    [p for p in net.parameters() if p.requires_grad], lr=1e-3)
print(sum(p.numel() for p in net.parameters() if p.requires_grad))

One line to remember. Freeze a layer with requires_grad = False. A frozen layer stays as it is; the other layers learn on top of it.
