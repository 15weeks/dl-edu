CNN - II

transfer learning과 style transfer

이미 학습된 network의 몸통을 빌려 와 새 문제에 쓰는 법(transfer learning), 깊은 CNN을 가능하게 한 residual connection, 그리고 feature의 통계(Gram matrix)로 그림의 무늬를 옮기는 style transfer.

1transfer learning: 무엇을, 왜, 언제

알고 싶은 것

label 붙은 그림이 몇백 장뿐이면? 다른 data로 이미 배운 network를 빌려 쓸 수 있나?

말로: 앞쪽 층은 경계·무늬처럼 어느 그림에나 쓰이는 것을, 뒤쪽 층은 그 data에만 맞는 것을 배운다. 그래서 앞쪽은 빌리고 끝(head)은 새로 단다.

for p in body.parameters():
    p.requires_grad = False            # 몸통 얼리기 (9장 8절)
model = nn.Sequential(body, nn.Linear(784, 10))   # 새 head
opt = torch.optim.Adam([p for p in model.parameters() if p.requires_grad], lr=1e-3)

기억할 한 줄. transfer learning = 다른 data로 배운 몸통 + 새 head. data가 적을수록 많이 얼린다.

2MNIST ↔ FMNIST: 작은 data로 transfer

알고 싶은 것

숫자(MNIST)로 배운 CNN 몸통이 옷(FMNIST) 500장 학습에 도움이 될까? 어느 층을 얼려야 하나?

방향
시작 값
1층
2층

결과: 11장의 CNN, 도착 data 500장 (class마다 50장), 40 epoch, 시험 10,000장, 3번 평균

→ 뜻. 빌려 오면 1~2%p 낫다: 작은 몸통이 배운 경계·획은 숫자와 옷에 다 쓰이지만, 두 data가 많이 달라서 이득이 크지는 않다. 무작위 kernel을 얼려 두기만 해도 72%가 나온다: 무작위 convolution도 쓸 만한 feature를 만든다. 몸통이 크고 출발 data가 클수록 이득이 커진다 (4절).

기억할 한 줄. 작은 data에서는 빌려 온 몸통이 무작위보다 낫다. 이득의 크기는 출발 data와 몸통이 얼마나 크고 비슷한지에 달렸다.

3유명한 CNN 구조: AlexNet, VGG, ResNet

알고 싶은 것

빌려 쓸 수 있는 큰 CNN에는 무엇이 있고, 어떻게 그렇게 깊어질 수 있었나?

이름 (해)conv · fc 층parameter핵심 생각
AlexNet (2012)5 · 361,100,840GPU, ReLU, dropout으로 ImageNet에서 큰 차이로 1등
VGG-16 (2014)13 · 3138,357,5443×3 conv만 깊게 쌓는다. 단순하지만 크다
ResNet-18 (2015)20 · 111,689,512residual connection: h + f(h). 152층까지 학습 가능

숫자는 torchvision 구조로 셌다 (weight 없이). ResNet-18의 "18"은 주된 길의 conv 17 + fc 1이고, 크기를 맞추는 지름길 1×1 conv 3개가 더 있어 conv는 20개다.

  • I 지름길이 gradient를 그대로(1배) 넘겨 주는 항

결과: 너비 32, tanh 30층, 30층 → 0층으로 gradient가 바뀐 배수 (무작위 5번 평균, 아래 그림과 같은 계산)

→ 뜻. 보통 층을 쌓으면 gradient가 층마다 곱해져 사라지기 쉽다 (9장 초기화). residual은 더하기 길 덕분에 깊어도 gradient가 입력 쪽까지 온다.

기억할 한 줄. AlexNet → VGG(깊게) → ResNet(지름길로 더 깊게). residual h + f(h)가 gradient를 살린다.

4ResNet-18, VGG-16으로 transfer (CIFAR10)

알고 싶은 것

ImageNet으로 학습한 큰 network를 빌리면 사진 5,000장만으로 얼마나 맞히나?

결과와 설정

CIFAR10 학습 5,000장 (class마다 500장), 시험 2,000장. 작은 CNN은 32×32 그대로 30 epoch. ResNet-18·VGG-16은 224×224로 키우고 ImageNet 평균·표준편차로 정규화, 몸통을 얼리고 마지막 Linear만 60 epoch. fine-tune은 112×112에서 전체를 4 epoch (lr 10⁻⁴).

→ 뜻. 몸통을 얼리고 마지막 한 층만 학습해도 작은 CNN을 처음부터 학습한 것보다 훨씬 낫다. ImageNet 128만 장에서 배운 feature가 CIFAR10 사진에도 그대로 쓰이기 때문이다.
m = torchvision.models.resnet18(weights="IMAGENET1K_V1")
for p in m.parameters():
    p.requires_grad = False
m.fc = nn.Linear(512, 10)                    # 새 head만 학습 (5,130개)

v = torchvision.models.vgg16(weights="IMAGENET1K_V1")
for p in v.parameters():
    p.requires_grad = False
v.classifier[6] = nn.Linear(4096, 10)        # 마지막 Linear만 새로 (40,970개)

기억할 한 줄. 사진 문제라면 먼저 ImageNet으로 학습한 network를 빌린다. 입력 크기와 정규화를 그 network에 맞춘다.

5autoencoder로 pretraining

알고 싶은 것

label은 500장뿐이지만 label 없는 그림은 60,000장 있다면? (10장 autoencoder)

결과: conv autoencoder (FMNIST 60,000장, 복원 MSE 0.0095) → encoder + 새 head를 500장으로

→ 뜻. 이 작은 실험에서는 이득이 0.5%p 남짓으로 작다 (3번의 흔들림과 비슷한 크기). 복원을 잘하는 feature와 분류에 좋은 feature가 꼭 같지는 않다. 요즘에는 같은 생각(label 없이 먼저 배우기)을 훨씬 큰 network와 data로 해서 큰 이득을 본다 (self-supervised learning).

기억할 한 줄. label 없는 data로 먼저 배우고(pretraining) 적은 label로 마무리한다. 이득의 크기는 실험으로 확인한다.

6style transfer와 Gram matrix

알고 싶은 것

그림의 "무늬(style)"를 숫자로 나타낼 수 있나? 무엇이 어디에 있는지는 빼고?

  • G_ij feature i와 j가 같은 자리에서 함께 켜진 정도

예제: feature map 3장, 각 4칸

F의 행 = 지도 하나를 편 것. G = F Fᵀ는 행끼리의 내적이다.

→ 뜻. 한 칸: G₁₂ = 1·1 + 0·1 + 1·0 + 0·0 = 1 (지도 1과 2가 첫째 자리에서만 같이 켜짐). 자리 k를 모두 더해 버리므로 "어디에"는 사라지고 "무엇과 무엇이 같이"만 남는다.

기억할 한 줄. Gram matrix = feature끼리의 내적. 자리를 버리고 함께 나오는 정도만 남긴다 = style.

7style transfer algorithm

알고 싶은 것

한 그림의 내용에 다른 그림의 무늬를 입히려면?

  • c 내용 그림
  • s 무늬 그림
  • x 만드는 그림 (pixel을 고친다)
  1. VGG-16을 빌려 와 얼린다. 학습하는 것은 network가 아니라 그림 x의 pixel이다.
  2. 내용: 깊은 층(relu4_2)의 feature map이 c와 같아지게 한다 → 무엇이 어디에 있는지.
  3. 무늬: 다섯 층(relu1_1 ~ relu5_1)의 Gram matrix가 s와 같아지게 한다 → 색과 결.
  4. x를 c에서 시작해 Adam으로 300번 고친다.
무늬

그림은 모두 tools/ch12_style.py가 직접 그린 것이다 (집 그림, 색유리 무늬, 물결 무늬). 160×160, VGG-16, Apple GPU(MPS)에서 한 번에 몇 초.

기억할 한 줄. style transfer = 얼린 CNN으로 잰 "내용 차이 + Gram 차이"를 pixel에 대해 gradient descent.
