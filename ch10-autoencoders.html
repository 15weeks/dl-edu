Autoencoder

Autoencoders and latent space

A network that squeezes a picture into a few numbers (encoder) and then unpacks them back into a picture (decoder). It needs no labels: the input is the target. Removing noise, filling in hidden parts, and latent space, which leads to the generative models of chapter 15.

1Autoencoders: compress, then rebuild

WHAT WE WANT TO KNOW

Can a 196-pixel digit be squeezed into 16 numbers and drawn again?

TERMS IN THIS SECTION

encoder
The front network that shrinks a picture x into a short code z.
decoder
The back network that unpacks the code z into a picture x̂.
bottleneck, latent code
The narrowest layer in the middle, and its values z (the hidden code).
  • x input picture (196 pixels)
  • z latent code (16 numbers)
  • x̂ rebuilt picture

In words: the input goes in the target slot as well. Because everything must pass through the narrow middle, the network learns to keep only "what matters in a digit" in 16 numbers.

WORKED EXAMPLE: one loss on a 4-pixel picture

196 pixels are too many to do by hand, so use 4. Square the difference between input x and rebuild x̂ in each pixel and average.

→ Meaning. Each pixel is off by about 0.12 on average (√0.015). The results from section 2 on (test MSE 0.0147 and so on) are the same formula averaged over 196 pixels and 10,000 test pictures.

One line to remember. Autoencoder = encoder (shrink) + decoder (unpack); loss = rebuild error. It learns without labels.

2Denoising autoencoders

WHAT WE WANT TO KNOW

What if noise goes into the input while the target stays clean?

  • x̃ noisy input
  • x clean target

RESULTS: 10,000 test images, MSE against the original

→ Meaning. The more noise, the bigger the gain (at 0.6 the error drops to a fifth). Noise does not fit the "shape of a digit", so it cannot squeeze through the narrow code.

One line to remember. Spoil the input, keep the target clean, and the autoencoder becomes a noise eraser.

3How many units the bottleneck needs

WHAT WE WANT TO KNOW

How much better is the rebuild with 1, 2, …, 64 units in the middle?

RESULTS: network 196-128-k-128-196, 6 epochs, test MSE

→ Meaning. The first few units bring the biggest gains; beyond 32 little changes. Too narrow gives a blurry "average digit"; wider is sharper but compresses less.

One line to remember. A narrower bottleneck compresses harder and blurs more. The bend in the error curve marks a good size.

4Restoring occluded parts

WHAT WE WANT TO KNOW

If part of the picture is blacked out, can the network bring the shape back?

RESULTS: 10,000 test images with rows 6–9 (4 rows) hidden

→ Meaning. When training the network of section 2, random bands of 2–5 rows were hidden along with the noise. So it reads the remaining strokes and fills in "for this digit, the middle should look like this". If the hidden part is what decides the digit, it may fill in a different digit.

One line to remember. A network that saw hidden parts in training fills them in "plausibly" at test time. It does not know the truth.

5The latent code and latent space

WHAT WE WANT TO KNOW

With a code of only 2 numbers, where on a plane do the digits land?

In words: each picture becomes one point on a plane. Click or drag on the plane below and the decoder draws the picture at that spot. Test MSE 0.030 (blurrier than with 16 numbers, since there are only 2).

One line to remember. Latent space = where the codes live. Similar pictures gather close together, and moving between them changes the picture smoothly.

6Tied weights

WHAT WE WANT TO KNOW

What if the decoder has no weights of its own and reuses the encoder weights, flipped (transposed)?

RESULTS: 196-32-196, same training settings

→ Meaning. Half the parameters, and in this experiment the error was even slightly smaller. Tying forces the encoder and decoder to fit each other, which acts like regularization (chapter 5).
z    = torch.relu(x @ W.T + b1)          # encoder: W (32×196)
xhat = torch.sigmoid(z @ W + b2)         # decoder: the same W, transposed

One line to remember. Tied weights: decoder = Wᵀ. Half the parameters, similar or better results.

7Bridge to generative models: new images from latent space

WHAT WE WANT TO KNOW

If any point in latent space goes into the decoder, does a new digit come out?

  • z_A code of digit A
  • z_B code of digit B
  • z(t) a point on the line between them

WORKED EXAMPLE: a 2-number code as in section 5, t = 1/4

Say A's code is (−1, 2) and B's is (3, 0). With t = 1/4 we take 3/4 of A and 1/4 of B, one number at a time.

→ Meaning. t = 0 gives z_A, t = 1 gives z_B, and values in between give points on the segment joining them. Fed to the decoder, such a point draws a picture partway from A to B.
This chapter's autoencoderChapter 15's generative models
Latent space has gaps and an arbitrary shapeVAE: shapes latent space like a normal distribution → any sampled point works
Removes noise in one go (section 2)Diffusion: removes noise a little at a time, many times → a new picture from pure noise

One line to remember. Between the data the pictures change smoothly, but nothing says where to sample. Setting that rule is the job of a generative model.
