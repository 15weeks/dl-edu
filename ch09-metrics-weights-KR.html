Metrics·Init

성능 측정과 weight 초기화

앞부분: 정확도 하나로는 안 보이는 것을 재는 법 (confusion matrix, precision, recall, F1). 뒷부분: 학습을 시작하는 weight를 어떻게 놓아야 깊은 network에서도 신호가 살아 있는지 (Xavier, Kaiming). 마지막에 FFN 프로젝트 셋.

1두 관점: confusion matrix

알고 싶은 것

"양성/음성"을 맞히는 model이 틀리는 방법은 두 가지다. 따로 세면?

이 절에 나오는 약자

TP, TN
true positive / negative. 양성을 양성으로, 음성을 음성으로 맞힘.
FP
false positive. 음성인데 양성이라고 함 (헛경보).
FN
false negative. 양성인데 음성이라고 함 (놓침).

예제: 음성 500, 양성 500, 문턱 0

→ 뜻. 문턱을 내리면 놓침(FN)은 줄고 헛경보(FP)는 는다. 둘 중 무엇이 더 나쁜지는 문제가 정한다 (암 검사: 놓침이 더 나쁘다).

기억할 한 줄. confusion matrix = 맞힘 둘(TP, TN)과 틀림 둘(FP 헛경보, FN 놓침). 문턱이 둘 사이의 저울이다.

2accuracy, precision, recall, F1

알고 싶은 것

네 칸을 숫자 하나로 요약하는 방법은?

  • precision "양성"이라고 한 것 중 진짜 비율 (헛경보가 적을수록 높다)
  • recall 진짜 양성 중 찾아낸 비율 (놓침이 적을수록 높다)
  • F1 둘의 조화 평균: 둘 다 높아야 높다

예제: 문턱 −1, 0, 1 (위 그림의 data)

→ 뜻. precision과 recall은 줄다리기를 한다. 문턱을 정할 때 무엇을 지킬지 먼저 정한다.

기억할 한 줄. precision = 헛경보를 싫어하는 숫자, recall = 놓침을 싫어하는 숫자, F1 = 둘 다.

3group 크기가 다를 때의 metric

알고 싶은 것

같은 model인데 양성이 1%뿐인 곳에 쓰면? (8장 7절의 불균형)

예제: 같은 점수 분포, 문턱 0, 1000개 중 양성 비율만 바꾸기

→ 뜻. accuracy는 계속 85% 근처지만, 양성이 1%면 경보 20개 중 19개가 헛경보다. "모두 음성"이라고만 해도 accuracy 99%. 드문 class에는 precision·recall·F1을 본다.

기억할 한 줄. 양성이 드물면 accuracy는 거의 아무것도 말해 주지 않는다. precision이 먼저 무너진다.

4계산 시간 재기, test가 train보다 좋을 때

알고 싶은 것

학습이 얼마나 걸리나? 시험 성적이 학습 성적보다 높으면 버그인가?

import time
t0 = time.perf_counter()
train_one_epoch(net, opt)
print(f"epoch 하나: {time.perf_counter() - t0:.2f} s")   # GPU면 torch.cuda.synchronize() 뒤에 잰다
test > train인 흔한 이유설명
dropout·augmentation학습 성적은 train mode(끄고, 비틀고)로 재고, 시험은 eval mode로 잰다 (5장 6절).
epoch 평균학습 성적이 epoch 동안의 평균이면 앞쪽의 나쁜 batch가 섞인다.
test가 작다시험 data가 적으면 우연히 쉬운 것이 몰릴 수 있다 (1장 10절의 흔들림).

기억할 한 줄. 시간은 perf_counter로 epoch마다. test > train은 대개 mode나 data 크기 때문이지 버그가 아니다.

for name, p in net.named_parameters():

0.weight (64, 196)

2.weight (10, 64)
2.bias (10,)

기억할 한 줄. nn.Linear(in, out).weight의 shape = (out, in). 행 하나 = neuron 하나.

6weight 초기화가 중요한 이유

알고 싶은 것

weight를 모두 0이나 같은 값으로 시작하면? 너무 크거나 작게 시작하면?

예제 1: XOR, 숨은 neuron 4개, 1000 epoch

→ 뜻. 같은 값으로 시작하면 숨은 neuron들이 같은 gradient를 받아 끝까지 똑같다 (대칭). 4개가 1개 몫밖에 못 한다. 그래서 weight는 무작위로 시작한다.

예제 2: tanh 10층(너비 64), weight 표준편차에 따른 10층 activation 표준편차

→ 뜻. 너무 작으면 층을 지날수록 신호가 0으로 사라지고, 너무 크면 tanh가 −1, 1에 붙어 기울기가 사라진다. 둘 다 학습이 멈춘다.

기억할 한 줄. 초기화는 무작위로, 크기는 알맞게: 너무 작으면 사라지고 너무 크면 포화한다.

7Xavier와 Kaiming 초기화

알고 싶은 것

"알맞은 크기"를 식으로 정할 수 있나?

이 절에 나오는 약자

Xavier (Glorot)
X. Glorot, Y. Bengio (2010). tanh·sigmoid에 맞춘 초기화.
Kaiming (He)
K. He 외 (2015). ReLU에 맞춘 초기화. ReLU는 절반을 0으로 만들어 분산이 반으로 주니 2배.
n_in, n_out
층의 입력 수, 출력 수 (fan-in, fan-out).

말로: 입력이 많을수록 더하는 항이 많아 합이 커지니, weight를 그만큼 작게 시작한다. 목표는 층을 지나도 분산이 그대로인 것.

결과: 20층 뒤 activation 표준편차 (너비 64, browser 계산)

→ 뜻. activation에 맞는 초기화를 써야 한다. ReLU에 Xavier를 쓰면 층마다 분산이 반씩 줄어 20층이면 사라진다. PyTorch의 nn.Linear 기본값은 Kaiming 계열(uniform)이다.
torch.nn.init.xavier_normal_(layer.weight)                         # tanh, sigmoid
torch.nn.init.kaiming_normal_(layer.weight, nonlinearity="relu")   # ReLU

기억할 한 줄. tanh·sigmoid에는 Xavier(2/(n_in + n_out)), ReLU에는 Kaiming(2/n_in).

8weight 얼리기와 학습에 따른 weight 변화

알고 싶은 것

층마다 weight는 얼마나 바뀌나? 일부 층은 고정할 수 있나? (12장 transfer learning의 바탕)

for p in net[0].parameters():
    p.requires_grad = False        # 1층 얼리기: gradient를 구하지 않는다
opt = torch.optim.Adam(
    [p for p in net.parameters() if p.requires_grad], lr=1e-3)
print(sum(p.numel() for p in net.parameters() if p.requires_grad))
650        # 5절 network: 196-64-10에서 2층(64×10 + 10)만 학습
1층

기억할 한 줄. requires_grad = False로 층을 얼린다. 얼린 층은 그대로, 나머지 층이 그 위에서 배운다.
