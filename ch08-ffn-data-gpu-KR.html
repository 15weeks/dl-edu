5universal approximation theorem

알고 싶은 것

숨은 층 하나짜리 FFN은 어떤 함수까지 흉내 낼 수 있나?

  • sigmoid 하나 = 계단 하나
  • v 계단 높이
  • N 계단 수 = 숨은 neuron 수

예제: 목표 곡선을 계단 N개로 (가장 큰 오차)

→ 뜻. "흉내 낼 수 있다"는 보장일 뿐, 그 weight를 학습으로 찾을 수 있다거나 적은 data로 일반화한다는 보장은 아니다. 그래서 실제로는 깊고 구조가 있는 network를 쓴다.

기억할 한 줄. 숨은 층 하나로도 어떤 연속 함수든 흉내 낼 수 있다 (neuron이 충분하면). 찾기 쉽다는 뜻은 아니다.

6Dataset과 DataLoader, data 크기와 network 크기

알고 싶은 것

내 data를 PyTorch에 넣는 틀은? data가 많아야 하나, network가 커야 하나?

import torch
from torch.utils.data import Dataset, DataLoader
class Digits(Dataset):                       # 내 data의 틀: 세 함수만 쓴다
    def __init__(self, X, y): self.X, self.y = X, y
    def __len__(self): return len(self.X)    # 몇 개?
    def __getitem__(self, i): return self.X[i], self.y[i]   # i번째 하나
ds = Digits(torch.rand(1000, 196), torch.randint(0, 10, (1000,)))
dl = DataLoader(ds, batch_size=64, shuffle=True)
xb, yb = next(iter(dl))
print(len(ds), len(dl), xb.shape, yb.shape)
1000 16 torch.Size([64, 196]) torch.Size([64])

결과: 학습 data 수 × 숨은 neuron 수 (PyTorch, 3000걸음씩)

→ 뜻. data가 적으면 network를 키워도 소용이 적다(81.6% vs 78.8%). data가 많아지면 큰 network가 그것을 살린다(96.7% vs 90.8%). 둘은 함께 키운다.

기억할 한 줄. Dataset = __len__ + __getitem__. 성능은 data 양과 network 크기가 함께 정한다.

7불균형 data, oversampling, augmentation

알고 싶은 것

"정상" 95%, "고장" 5%인 data라면? data가 모자라면 늘릴 수 있나?

이 절에 나오는 약자

recall
(재현율). 적은 class 가운데 찾아낸 비율 (9장에서 자세히).
oversampling
적은 class를 여러 번 넣어 수를 맞추기.
augmentation
(증강). 조금 움직이고 돌리고 잡음을 넣어 새 학습 예제를 만들기.

예제: 400개 중 적은 class 5% (20개)

→ 뜻. 그대로 학습하면 "전부 많은 class"라고 답해서 정확도 95%를 받는다. 적은 class를 맞추려면 수를 맞추거나(oversampling), loss에 무게를 주고, 정확도 말고 recall을 본다.
oversampling

기억할 한 줄. 불균형이면 정확도에 속는다: 수를 맞추고 recall을 본다. data가 모자라면 의미를 해치지 않는 변형으로 늘린다.

8model 저장, 가장 좋은 model 남기기, GPU

알고 싶은 것

학습이 끝나면 무엇을 남기나? 어느 epoch의 것을? GPU로는 어떻게 옮기나?

결과 (학습 1000장으로 일부러 overfitting)

→ 뜻. 마지막 epoch가 가장 좋은 것이 아니다. dev가 가장 좋았던 순간의 weight를 따로 저장해 둔다 (early stopping의 생각).
import copy, torch
best_acc, best_state = 0.0, None
for epoch in range(40):
    train_one_epoch(net, opt)                       # 학습
    dev_acc = evaluate(net, dev_loader)             # dev로 재기 (eval mode, 5장)
    if dev_acc > best_acc:
        best_acc, best_state = dev_acc, copy.deepcopy(net.state_dict())
torch.save(best_state, "best.pt")                   # 저장: weight만 (state_dict)
net.load_state_dict(torch.load("best.pt"))          # 불러오기
device = "cuda" if torch.cuda.is_available() else ("mps" if torch.backends.mps.is_available() else "cpu")
net = net.to(device)                                # model을 GPU로
xb, yb = xb.to(device), yb.to(device)               # data도 같은 장치로

GPU는 같은 계산(행렬 곱)을 수천 개 동시에 한다. model과 data가 같은 장치에 있어야 하고, 바꿀 것은 .to(device) 두 줄뿐이다. Apple 칩은 "mps".

기억할 한 줄. state_dict를 저장하고, dev가 가장 좋았던 것을 남기고, model과 data를 같은 device로.
