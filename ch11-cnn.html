CNN - I

Convolution and pooling

Look at a picture as a 2-D grid instead of unrolling it into a line. A small kernel slides over the picture and finds the same pattern (a stroke, an edge) wherever it is, and pooling shrinks the picture. Fewer parameters than the FFN of chapter 8, and higher accuracy.

1Convolution: a kernel sliding over the image

WHAT WE WANT TO KNOW

Can one small grid of numbers find where a picture has a "vertical edge"?

TERMS IN THIS SECTION

CNN
convolutional neural network. A neural network with convolution layers.
kernel (filter)
A small grid of weights that slides over the picture (3×3 here).
feature map
The output picture the kernel makes as it slides: a map of "where, and how strongly, this pattern appears".
  • x input picture
  • k kernel
  • y output (feature map)

In words: lay the kernel over the picture, multiply the 9 overlapping cells pairwise and add them all up: one output cell. Move one step and repeat. The same kernel is used across the whole picture (weight sharing).

WORKED EXAMPLE: the single output cell (2, 0)

Multiply the window at rows 2–4, columns 0–2 of the input by the vertical-edge kernel cell by cell, and add.

→ Meaning. Dark on the left and bright on the right gives a large positive number, the reverse a large negative one, and a flat area 0. This kernel is a "vertical-edge detector". (Deep learning's convolution is the mathematician's cross-correlation: the kernel is not flipped.)
kernel

One line to remember. Convolution = slide a small kernel, multiply cell by cell, add. The same kernel finds the same pattern anywhere in the picture.

3Stride, padding and the output-size formula

WHAT WE WANT TO KNOW

If the kernel moves two cells at a time, or the picture gets a border of zeros, how many cells does the output have?

TERMS IN THIS SECTION

N, K
Cells along one side of the input and of the kernel.
S (stride)
How many cells the kernel moves at a time.
P (padding)
How many rings of zeros go around the edge.

WORKED EXAMPLES

→ Meaning. Padding (K − 1)/2 with stride 1 keeps the size ("same"); stride 2 halves it. Without padding, every layer loses K − 1 cells.

One line to remember. O = ⌊(N + 2P − K)/S⌋ + 1. Every CNN shape calculation is this one line.

4Transpose convolution

WHAT WE WANT TO KNOW

If convolution shrinks a picture, what layer grows it back? (the decoder of chapter 10, U-Net in chapter 12)

In words: each input cell stamps (its value × the kernel) onto the output like a rubber stamp. Stamps are placed stride cells apart, and where they overlap they add up.

WORKED EXAMPLE: 2×2 input, 3×3 kernel (all ones), stride 2

→ Meaning. The centre 10 = 1 + 2 + 3 + 4: all four stamps overlap there. The kernel is learned too, so the layer learns "how to grow". (Checked with PyTorch F.conv_transpose2d.)
stride
up = nn.ConvTranspose2d(16, 8, kernel_size=3, stride=2)   # (16, 7, 7) → (8, 15, 15)

One line to remember. Transpose convolution = stamp value × kernel and add. It grows the picture: O = (N − 1)S − 2P + K.

5Max and mean pooling; pool or stride?

WHAT WE WANT TO KNOW

What is the simplest way to halve a feature map?

WORKED EXAMPLE: 4×4 → 2×2 (one value per 2×2 block)

→ Meaning. Max keeps only "was the pattern in this block?": if the pattern moves by a cell or two, the answer often stays the same. There are no parameters to learn.
Way to shrinkCodeParametersCharacter
max poolnn.MaxPool2d(2)0A fixed rule. Fast, and robust to small shifts.

7Classifying MNIST and Gaussians; looking inside feature maps

WHAT WE WANT TO KNOW

What does a CNN do better than an FFN?

RESULTS: MNIST 28×28, 3 epochs, 10,000 test images (PyTorch)

→ Meaning. Less than a quarter of the parameters, and more accurate. Sharing one kernel across the picture needs few weights, and it uses what pictures are like: nearby cells belong together.

RESULTS: digits moved sideways (no shifting during training)

→ Meaning. The same kernel finds the same pattern anywhere, and pooling absorbs small shifts, so the CNN holds up far better. Move the digit a lot and the CNN drops too: it is not fully shift-invariant.

RESULTS: Gaussian width classification (4,000 training, 1,000 test images)

→ Meaning. The task is to measure the "width" of a round blob wherever it sits. Wherever it moves, the same kernel measures the same shape.

One line to remember. A CNN uses what pictures are like ("nearby cells, same pattern anywhere") with few weights. That is why it is more accurate and more robust to shifts.

8Image transforms and custom DataLoaders

WHAT WE WANT TO KNOW

How do we alter the training pictures a little every time? How do we feed our own data to a DataLoader?

from torchvision import transforms as T
train_tf = T.Compose([
    T.RandomRotation(15),
    T.RandomAffine(0, translate=(0.1, 0.1)),
    T.ToTensor(),                      # PIL → (C, H, W), 0 to 1
    T.Normalize((0.5,), (0.5,)),       # → −1 to 1
])
test_tf = T.Compose([T.ToTensor(), T.Normalize((0.5,), (0.5,))])
class MyData(torch.utils.data.Dataset):
    def __init__(self, imgs, labels, tf=None):
        self.imgs, self.labels, self.tf = imgs, labels, tf
    def __len__(self):
        return len(self.imgs)
    def __getitem__(self, i):          # one at a time, transformed on the fly
        x = self.imgs[i]
        if self.tf: x = self.tf(x)
        return x, self.labels[i]
loader = torch.utils.data.DataLoader(
    MyData(imgs, labels, train_tf), batch_size=64, shuffle=True)

One line to remember. Random transforms on training data only; Normalize on both training and test. A Dataset needs just __len__ and __getitem__.
