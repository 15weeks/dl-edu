Optimizer

mini-batch, optimizer, learning rate

2장의 gradient descent를 실제로 빠르고 안정되게 만드는 방법들: data를 조금씩 나눠 쓰기(mini-batch), 속도 쌓기(momentum), 방향마다 걸음 맞추기(RMSprop, Adam), 시간에 따라 걸음 줄이기(schedule), 그리고 이 설정들을 고르는 법.

1mini-batch 학습과 batch 크기

알고 싶은 것

data가 백만 개면 한 걸음마다 백만 개의 gradient를 다 더해야 하나?

이 절에 나오는 약자

batch
한 걸음에 쓰는 sample 묶음. B = 그 크기.
SGD
stochastic gradient descent. 무작위로 고른 batch로 걷는 GD.
epoch
data 전체를 한 번 다 쓰는 것 = N / B 걸음.
  • g_B batch로 잰 gradient (전체 gradient의 어림)
  • B 작으면 걸음이 많고 흔들리고, 크면 걸음이 적고 곧다

예제: N = 256

→ 뜻. 작은 batch는 싸고 자주 걷지만 방향이 흔들린다(이 흔들림이 오히려 overfitting을 조금 막기도 한다). GPU에서는 32~256이 흔하다.
batch 크기

기억할 한 줄. mini-batch = 전체 gradient를 batch로 어림해 자주 걷는다. batch가 작을수록 흔들리고, 클수록 곧지만 비싸다.

2SGD와 momentum

알고 싶은 것

2장 8절의 길쭉한 골짜기에서 완만한 방향으로 기어가는 문제를 어떻게 푸나? 굴러가는 공처럼 속도를 기억한다.

  • v 속도: 지난 gradient들의 누적
  • β 기억하는 정도 (보통 0.9)
  • g 이번 gradient
  • 같은 방향이 계속되면 속도가 쌓인다 (굴러가는 공처럼)

예제: f = (x² + 50y²)/2, (−4.5, 1)에서 η = 0.035로 40걸음

→ 뜻. 같은 η인데 momentum이 90배 낮다. 완만한 x 방향으로 속도가 쌓여 빨리 간다. 대신 가파른 y 방향으로는 출렁인다: β = 0.9면 이 골짜기에서 너무 출렁여 오히려 늦다.

기억할 한 줄. momentum = gradient를 쌓아 속도로 걷는다. 일관된 방향은 빨라지고, β가 너무 크면 출렁인다.

3RMSprop과 Adam

알고 싶은 것

방향마다 가파른 정도가 다르면, 방향마다 걸음 크기를 따로 정할 수 없나?

이 절에 나오는 약자

RMSprop
root mean square propagation. gradient 크기의 이동 평균으로 나눈다.
Adam
adaptive moment estimation. momentum + RMSprop.
m̂, v̂
처음 몇 걸음의 치우침(0에서 시작)을 바로잡은 m, v.
  • m 방향의 평균 (momentum)
  • s, v 크기의 평균: 가파른 방향일수록 크다 → 나누면 걸음이 작아진다
  • Adam 기본값: η = 0.001, β₁ = 0.9, β₂ = 0.999

예제: 2절과 같은 골짜기, 40걸음

→ 뜻. g/√s ≈ 부호만 남긴 걸음이라 x, y가 같은 크기로 줄어든다. 이 골짜기에서는 RMSprop이 가장 빠르고, Adam은 momentum 때문에 조금 넘친다. 어떤 optimizer가 언제나 이기지는 않는다.

기억할 한 줄. RMSprop·Adam = 방향마다 gradient 크기로 나눠 걸음을 맞춘다. Adam은 거기에 momentum까지. 대부분의 딥러닝의 기본값.

4optimizer 비교

알고 싶은 것

굽은 골짜기와 진짜 network에서는 누가 빠른가?

결과: f = (1 − x)² + 5(y − x²)², (−1.5, 2.2)에서 300걸음

→ 뜻. 굽은 골짜기에서는 momentum과 Adam이 바닥까지 간다. η는 optimizer마다 따로 맞춰야 한다 (같은 η로 비교하면 불공평하다).

해 볼 것

  1. 경주: 네 공이 동시에 출발한다. 지도를 누르면 출발점이 바뀐다.

해 볼 것

  1. 네 가지 같이 학습: 같은 network, 같은 출발 weight. loss가 0.37 근처 평평한 곳(plateau)에 한동안 머무는데, RMSprop·Adam이 먼저 빠져나온다.

기억할 한 줄. 처음에는 Adam(η ≈ 0.001)으로 시작한다. 마지막 성능을 짜낼 때 SGD + momentum + schedule도 시도한다.

5Adam + L2와 AdamW

알고 싶은 것

5장의 L2(weight decay)를 Adam과 같이 쓰면 그대로 작동하나?

말로: Adam + L2는 벌점도 gradient에 섞여 √v로 나뉜다. gradient가 큰 weight는 벌도 작게 받는다. AdamW는 벌을 따로 빼서 모든 weight에 똑같이 준다.

torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=0.01)    # Adam + L2 (벌이 √v로 나뉜다)
torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.01)   # AdamW (벌을 따로, 요즘 기본)

기억할 한 줄. Adam에 weight decay를 쓸 때는 AdamW. Transformer(14장)도 AdamW로 학습한다.

6learning rate decay와 schedule

알고 싶은 것

2장 6절의 "처음엔 크게, 나중엔 작게"를 어떤 모양으로?

  • η₀ 처음 η
  • γ 줄이는 비율
  • T 전체 epoch
  • warmup 처음 몇 epoch은 0에서 천천히 올린다 (Adam·Transformer에서 흔함)
opt = torch.optim.SGD(model.parameters(), lr=0.1, momentum=0.9)
sched = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=100)   # StepLR, ExponentialLR도 있다
for epoch in range(100):
    train_one_epoch(model, opt)       # 그 안에서 opt.step()
    sched.step()                      # epoch마다 η를 바꾼다

기억할 한 줄. schedule = 처음엔 크게 걸어 빨리 가고 끝에서 작게 걸어 바닥에 앉는다. cosine(+ warmup)이 요즘 흔하다.

metaparameter
hyperparameter라고도 한다. 학습이 아니라 사람이 정하는 설정.
grid search
값을 격자로 정해 모두 시도.
