FFN

MNIST, handling data, GPUs

We build one FFN end to end on handwritten digits (MNIST). A network actually trained on MNIST lives inside this page, so it answers as soon as you draw a digit. Then we look at what FFNs cannot do, practical data problems (size, imbalance, augmentation), saving models and GPUs.

1Fully-connected, feedforward networks

WHAT WE WANT TO KNOW

How do we feed a picture into chapter 3's network? Lay its 784 numbers out in one line.

TERMS IN THIS SECTION

FFN
feedforward network. A network where everything flows forwards. All the networks of chapters 3–7 are FFNs.
fully-connected
Every value in one layer connects to every neuron in the next. PyTorch's nn.Linear.
MNIST
Modified National Institute of Standards and Technology handwritten digits: 60,000 training and 10,000 test images, 28 × 28.

WORKED EXAMPLE: this chapter's network (2×2 averages give 14 × 14 = 196 inputs)

→ Meaning. Once unrolled, the network is no longer told which cell sits next to which. Section 4 shows what that means.

One line to remember. To feed a picture to an FFN, unroll its pixels into one line. Every input connects to every neuron.

STANDARD DEVIATION OF THE LAYER-1 WEIGHTS

→ Meaning. They start as small, even random values and spread out as training goes on. Fold one neuron's 196 weights back into 14 × 14 and a pattern appears: "+ where ink should be, − where it should not".

4Scrambled and shifted MNIST: what an FFN cannot see

WHAT WE WANT TO KNOW

Does an FFN know the "shape" of a digit, or only "which cell"?

RESULTS (PyTorch, same network)

→ Meaning. People cannot read the scrambled picture, but an FFN learns it just as well, because it never uses which cells are neighbours. That is also why shifting a digit by 2–3 pixels breaks it. CNNs (chapter 11) fix both.

One line to remember. An FFN reads "which cell has ink". It knows nothing of neighbours, nor that a shifted shape is the same shape.

5The universal approximation theorem

WHAT WE WANT TO KNOW

Which functions can an FFN with a single hidden layer imitate?

  • one sigmoid = one step
  • v step height
  • N number of steps = hidden neurons

WORKED EXAMPLE: the target curve with N steps (largest error)

→ Meaning. "Can imitate" is only a guarantee that such weights exist, not that training will find them or that they generalise from little data. That is why real networks are deep and structured.

One line to remember. One hidden layer can imitate any continuous function (with enough neurons). That does not make it easy to find.

6Dataset and DataLoader; data size and network size

WHAT WE WANT TO KNOW

What frame puts my own data into PyTorch? Do we need more data or a bigger network?

import torch
from torch.utils.data import Dataset, DataLoader
class Digits(Dataset):                       # a frame for my data: only three functions
    def __init__(self, X, y): self.X, self.y = X, y
    def __len__(self): return len(self.X)    # how many?
    def __getitem__(self, i): return self.X[i], self.y[i]   # item number i
ds = Digits(torch.rand(1000, 196), torch.randint(0, 10, (1000,)))
dl = DataLoader(ds, batch_size=64, shuffle=True)
xb, yb = next(iter(dl))
print(len(ds), len(dl), xb.shape, yb.shape)
1000 16 torch.Size([64, 196]) torch.Size([64])

RESULTS: training images × hidden neurons (PyTorch, 3000 steps each)

→ Meaning. With little data a bigger network helps little (81.6% vs 78.8%). With lots of data the bigger network makes use of it (96.7% vs 90.8%). Grow them together.

One line to remember. Dataset = __len__ + __getitem__. Performance is set by the amount of data and the size of the network together.

7Unbalanced data, oversampling and augmentation

WHAT WE WANT TO KNOW

What if the data are 95% "normal" and 5% "faulty"? If data are scarce, can we make more?

TERMS IN THIS SECTION

recall
The share of the rare class that is found (more in chapter 9).
oversampling
Repeat the rare class to even out the numbers.
augmentation
Make new training examples by small shifts, rotations and noise.

WORKED EXAMPLE: 400 points, 5% (20) in the rare class

→ Meaning. Trained as is, it answers "common" every time and still scores 95%. To catch the rare class, even out the numbers (oversampling) or weight the loss, and look at recall rather than accuracy.
oversampling

One line to remember. With unbalanced data accuracy fools you: even out the numbers and watch recall. Short of data, add variations that keep the meaning.

8Saving models, keeping the best one, GPUs

WHAT WE WANT TO KNOW

What do we keep when training ends, and from which epoch? How do we move to a GPU?

RESULT (1000 training images, deliberately overfitting)

→ Meaning. The last epoch is not the best. Save the weights from the moment the dev score peaked (the idea behind early stopping).
import copy, torch
best_acc, best_state = 0.0, None
for epoch in range(40):
    train_one_epoch(net, opt)                       # train
    dev_acc = evaluate(net, dev_loader)             # measure on dev (eval mode, chapter 5)
    if dev_acc > best_acc:
        best_acc, best_state = dev_acc, copy.deepcopy(net.state_dict())
torch.save(best_state, "best.pt")                   # save: the weights only (state_dict)
net.load_state_dict(torch.load("best.pt"))          # load
device = "cuda" if torch.cuda.is_available() else ("mps" if torch.backends.mps.is_available() else "cpu")
net = net.to(device)                                # model onto the GPU
xb, yb = xb.to(device), yb.to(device)               # data onto the same device

A GPU runs thousands of the same calculation (matrix products) at once. The model and the data must sit on the same device, and the only change is two .to(device) lines. Apple chips use "mps".

One line to remember. Save the state_dict, keep the one with the best dev score, and put the model and data on the same device.
